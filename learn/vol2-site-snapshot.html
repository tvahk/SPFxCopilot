02 Libraries we use, and why

Common Microsoft libraries so the result looks native and you write less code.

Fluent UI v8

The Microsoft control set: DetailsList, Pivot, CommandBar, ProgressIndicator, Persona, MessageBar. Import per module to keep the bundle small.

PnP React controls

@pnp/spfx-controls-react. We use FileTypeIcon for native file icons. Only context-free controls are safe inside a Copilot component.

PnPjs v4

@pnp/graph for the Graph reads (site, drive, items, permissions) and me.sendMail. Clean, typed, and familiar from your web parts.

# install the libraries (Fluent UI is usually already present)
npm install @fluentui/react@^8 @pnp/sp@^4 @pnp/graph@^4 @pnp/spfx-controls-react@^3
Version reality. @pnp/spfx-controls-react v3 officially reaches SPFx 1.23 and is not yet validated on 1.24 with React 18. Install the latest v3, use only context-free controls (like FileTypeIcon) inside a Copilot component, and test carefully. Fluent UI must be v8, not v9.

03 The architecture: presentation-first

The most important decision in this build, and it is about honesty with the preview.

Why not just call Graph from the component? A Copilot component's context is only documented to expose domElement, hostContext (theme and display mode), and requestDisplayModeAsync. It is not documented to expose the token or Graph factories that PnPjs needs, so calling Graph directly from the component may not work in the Copilot canvas in preview.

So the UI never talks to Graph. It depends on a small seam, and two implementations satisfy it. You build and demo the whole UI on mock data, then swap in the real one by changing a single line.

UI

Components

Inline card and fullscreen dashboard. They only know the seam.

Seam

Sample data. No tenant, no permissions. UI works from M1.

Then swap

GraphDataSource

PnPjs Graph. One line change. Verify in preview; fall back to AadHttpClient if the context cannot bind.

copilot/The declarative agent.The agent definition, plugin, instructions, and app manifest that make the tools callable in Copilot.

05 Conventions we follow

The same rules you use on your own SPFx apps. Full list in docs/05.

SCSS modules, not inline styles

Layout and spacing live in .module.scss files. Fluent themes the controls. The only inline style is a CSS variable driven by data, like the score ring fill.

One service per domain

All data access sits in services/ behind the seam. Components never call Graph.

Shared utils and colors

Format dates with formatDate, style buttons from BUTTON_STYLES. Never redefine them locally.

Hooks at the top

Every hook is declared before any early return, and no component is defined inside another's render. This avoids the React #300 error.

Deterministic and throttle-safe

Pass the clock in rather than reading it inside. Cap the item scan, batch permission checks, cache reads, and report when results are capped.

Bundle discipline

Import Fluent per module. Keep heavy extras like a chart library out of the initial bundle with a dynamic import.

06 Build it in milestones

Each milestone leaves you with something that runs. Expand one at a time.

M0 Plumbing and dependencies

Scaffold a Copilot Component (React) as in docs/02, install the libraries, and get a thin class rendering a placeholder in both display modes.

// SiteSnapshotCopilotComponent.ts - keep it thin
export default class SiteSnapshotCopilotComponent
  extends BaseCopilotComponent<typeof AnalyzeSiteProperties> {
  public render(): void {
    const args = this.properties as AnalyzeSiteArgs;
    const isFullscreen = this.hostContext.displayMode === 'fullscreen';
    const isDark = this.hostContext.theme === 'dark';
    ReactDOM.render(
      React.createElement(SiteSnapshotApp, {
        siteUrl: args.siteUrl, staleMonths: args.staleMonths ?? 6, topN: args.topN ?? 10,
        isFullscreen, isDark, onRequestFullscreen: this._goFullscreen,
      }),
      this.context.domElement
    );
  }
  private _goFullscreen = async () => { try { await this.requestDisplayModeAsync('fullscreen'); } catch {} };
  protected onHostContextChanged(): void { this.render(); }
}
Checkpoint: run npx heft start --nobrowser, open the Copilot Workbench, and see your placeholder render inline and fullscreen.

M3 Real data with PnPjs

Implement the same seam with @pnp/graph: resolve the site, read the drive quota, page the item children, and batch the permission checks. Then switch the app to it.

// services/graphDataSource.ts (preview: verify the context binds; see the file header)
this.graph = graphfi().using(SPFx(context as any));
const site = await this.graph.sites.getByUrl(u.hostname, u.pathname)();
const drive = await this.graph.drives.getById(driveId)();   // drive.quota.used / .total
const children = await drive.root.children.top(200)();       // page, cap at 500
const perms = await drive.items.getById(id).permissions();   // batch in tens
If SPFx(context) does not bind in the Copilot canvas, fall back to AadHttpClient, or move the Graph calls to the agent tool layer and pass results in as properties. Keep the mock source for the Workbench.
Checkpoint: after approving the Graph permissions, run against a real site and see accurate storage, stale, and sharing numbers.

Add utils/csvExport.ts and wire the exportSnapshot tool to the Export button on the CommandBar. Export is pure client-side, so it needs no data source.

M5 The email action

Add emailSnapshot in the service, sending an HTML summary through the data source (graph.me.sendMail, or the AadHttpClient fallback). Fill in the scenario copilot/ai-plugin.json and instruction.txt.

Add friendly errors and a MessageBar empty state, cache the reads, expose the tool arguments (staleMonths, topN), move text into loc/, refine the theme, and bump the solution version before you deploy.
